# Prism 颜色对话框接管工具：取色面板方案设计

- 版本：v1
- 日期：2026-11-13
- 目标环境：Windows + GraphPad Prism 10.6.0.890（`D:\prism\X`）
- 运行环境：`D:\Conda\envs\dock\python.exe`（Python 3.12.9 + pywin32 + tkinter 8.6，零安装）
- 状态：**Phase 0 已于 2026-11-13 18:18 实测完成，核心假设全部成立**；尚未实现
- 实测记录：`输出/Dialog探测报告_v1_20261113_181832.md`

---

## 一、要解决的问题

Prism 里给数据点或柱子设一个非预设色，要走六步：Format Graph → 颜色下拉 → More Colors → 先点一个基本色（否则数值框不激活）→ 逐格改 R、G、B → Add to Custom Colors → OK。

其中"逐格改三个十进制数"是纯机械劳动。人想到的是"这个蓝"，不是 (46, 90, 136)。

本方案要做的，是让这一步变成"点一下"或"吸一下"。

---

## 二、方案定位

### 2.1 做的事

在 Prism 弹出颜色对话框的瞬间识别它，在旁边浮出自己画的取色面板。用户从面板选色，工具把结果写进对话框的三个数值框。

### 2.2 不做的事

- **不修改 Prism 安装文件**。`D:\prism` 下任何文件都不动。
- **不替换系统颜色对话框**。不做 API Hook、不注入 DLL。系统上其他程序的颜色对话框不受影响。
- **不解析 Prism 项目文件**。这条路已单独评估，见 `备选_PCFFGRA4颜色字段定位_方案设计_v1.md`，暂不推进。

### 2.3 为什么只能这么做

官方文档明确两条：Prism 不提供 API（"Does Prism have an API that can be called from other programs? No."），且那个颜色对话框属于 Windows 而非 GraphPad（"part of Windows and was not created by GraphPad"）。

前者堵死"做插件"，后者说明"换掉对话框"等于改系统组件。剩下唯一可行的就是旁路接管——对话框照常弹出，工具在外面接手交互。

## 三、核心机制

### 3.1 整体流程

```
Prism 弹出颜色对话框
        │
        ▼
[识别] 窗口类名 + 标题 + 所有者链上的进程
        │ 命中
        ▼
[定位] 用控件 ID 找到 R/G/B 三个编辑框与 Add 按钮
        │
        ▼
[浮出] 取色面板出现在鼠标附近，不抢焦点
        │ 用户选色
        ▼
[写回] 三级降级：消息写入 → 键盘模拟 → 剪贴板兜底
        │
        ▼
[可选] 自动点 Add to Custom Colors，再点 OK
```

### 3.2 对话框识别

这是整个方案的第一道关卡，也是最容易出错的地方。

**监听方式**：`SetWinEventHook` 挂 `EVENT_OBJECT_CREATE`（0x8000）与 `EVENT_SYSTEM_FOREGROUND`（0x0003）。窗口创建时立即回调，不需要轮询，空闲时 CPU 占用接近零。pywin32 通过 `win32gui.SetWinEventHook` 提供。

**判定条件**，三条必须同时成立：

1. **窗口类名是 `#32770`**。这是 Windows 对话框的通用类名。若 Prism 用了自绘窗口，这条不成立，见 §8 的降级方案。
2. **标题命中候选集**。**实测结果：Prism 10.6 英文版的实际标题是 `Choose Color`**，不是预期中的 `Color`。中文版可能为"颜色"。候选集写进配置文件，判定用子串匹配而非精确匹配，这样 `Color` 也能覆盖 `Choose Color`。
3. **所有者链上出现 Prism 进程**。这一条要特别处理，原因见下。

**关于 OLE 就地激活**：从 PPT 双击打开 Prism 对象时，Prism 不是独立进程窗口，而是嵌入在 PowerPoint 窗口内的子窗口。此时颜色对话框的所有者直接指向 PowerPoint 的窗口，只看一层会误判。正确做法是沿 `GetWindow(hwnd, GW_OWNER)` 向上追溯最多五层，链上任意一层属于 Prism 进程即判定命中；同时也要检查对话框自身的进程（独立运行时对话框由 Prism 直接创建）。

**实测修正**：2026-11-13 的探测正好是在 OLE 就地激活状态下做的（从 `Fig2.pptx` 双击打开）。实际所有者链为：

```
Choose Color (#32770, prism.exe)
  └─ 所有者 → Format Graph (#32770, prism.exe)
       └─ 所有者 → IPMainClass10, 标题 "Object in Fig2.pptx - GraphPad Prism 10.6.0 (890)", prism.exe
```

三层进程全是 `prism.exe`。也就是说，**OLE 就地激活时 Prism 仍持有独立的主窗口对象，对话框本身就在 Prism 进程内，仅凭进程名即可命中**。所有者链追溯保留作为冗余保险，不是必需条件。这一条比预想的更乐观。

伪代码：

```
def is_target_dialog(hwnd):
    if get_class_name(hwnd) != "#32770":
        return False
    if get_title(hwnd) not in TITLE_CANDIDATES:
        return False
    if get_pid(hwnd) in prism_pids:
        return True
    h = hwnd
    for _ in range(5):
        h = get_window(h, GW_OWNER)
        if not h:
            break
        if get_pid(h) in prism_pids:
            return True
    return False
```

`prism_pids` 在启动时枚举一次进程名为 `prism.exe` 的进程，之后每次判定前刷新（Prism 可能中途启动）。

### 3.3 控件定位

对话框内部控件按 Windows SDK 的 `dlgs.h` 常量定位：

| 常量 | 值 | 用途 |
|---|---|---|
| `COLOR_RED` | 706 | 红通道输入框 |
| `COLOR_GREEN` | 707 | 绿通道输入框 |
| `COLOR_BLUE` | 708 | 蓝通道输入框 |
| `COLOR_ADD` | 712 | "添加到自定义颜色"按钮 |
| `IDOK` | 1 | "确定"按钮 |

用 `GetDlgItem(hDlg, id)` 取句柄。**上述五个 ID 已于 2026-11-13 在 Prism 10.6.0.890 上实测确认，全部吻合**：706/707/708 的类名为 `Edit`，712 的文本为 `&Add to Custom Colors`，1 的文本为 `OK`。

**Prism 在标准对话框上追加了五个控件**（标准 ChooseColor 没有这些），实测发现：

| 控件 ID | 类名 | 内容 | 用途 |
|---|---|---|---|
| 1115 | `Button` | `Use these custom colors in new projects` | 复选框 |
| 729 | `Static` | `&Transparency:` | 透明度标签 |
| 1116 | `msctls_trackbar32` | 空 | 透明度滑块 |
| 1117 | `Edit` | 空 | 透明度数值框 |
| 2712 | `Static` | 空，59×58 | 当前颜色预览 |

这些追加控件说明 Prism 在对话框初始化时做了扩展，但**没有改动 RGB 三个框的 ID**。对本方案的实现没有影响，但要注意 1117 也是 `Edit` 类，做启发式定位时必须排除它（它是透明度，不是颜色通道）。

**透明度必须一并处理（实测发现，2026-11-13）**：把这个对话框的 RGB 写成纯红 `255/0/0` 之后，预览色块显示出来是**粉红色而不是纯红**，原因是 1117 里的透明度当前为 `49%`——49% 的红色叠在白色底上，肉眼看到的就是粉色。

这一条对设计有直接影响：若面板只写 RGB、不管透明度，用户会觉得"颜色不对"，实际上是被原有透明度冲淡了。因此实现时：

1. 面板打开时读取 1117 的当前值，显示在面板上（例如"不透明度 51%"）；
2. 提供调节入口，写回 1117 并同步滑块 1116；
3. 提供"恢复不透明"按钮，把 1117 写 0。

（Windows 对话框里的"Transparency 49%"表示 49% 透明，等价于 51% 不透明。面板上建议统一用"不透明度"表述，避免歧义。）

另一个实测细节：对话框刚打开时，706/707/708 三个框的文本都是空的。这与官方文档的描述一致——必须先点一个基本颜色，RGB 数值框才会填入当前值。这一条对写入方案有利：意味着不必先模拟点击基本色，直接 `WM_SETTEXT` 即可。

所有控件 ID 写进 `config.json`，不硬编码。这样一来，即使 Prism 后续版本改了布局，改配置即可，不用改代码。

**若 ID 不匹配的降级**：遍历对话框的子控件，找三个相邻的、类名为 `Edit` 且能通过 `GetWindowText` 读出纯数字的控件，按顺序当作 R、G、B。这种启发式定位比固定 ID 脆弱，但通常有效。

### 3.4 颜色写回

三级降级，前一级失败自动退到下一级。

**第一级：消息写入**

```
SendMessage(hEditR, WM_SETTEXT, 0, "46")
SendMessage(hEditG, WM_SETTEXT, 0, "90")
SendMessage(hEditB, WM_SETTEXT, 0, "136")
```

写入后对话框的预览色块可能不刷新（因为 `WM_SETTEXT` 不产生 `EN_CHANGE` 通知）。补发：

```
PostMessage(hDlg, WM_COMMAND, MAKEWPARAM(706, EN_CHANGE), hEditR)
```

若仍不刷新，改为写入前先 `SetFocus(hEditR)`，利用控件自身的输入处理逻辑触发。

**第二级：键盘模拟**

```
SetForegroundWindow(hDlg)
SetFocus(hEditR) → Ctrl+A → 键入 "46" → Tab → 键入 "90" → Tab → 键入 "136"
```

稳定但会抢焦点，速度约 200 毫秒，且受输入法状态干扰。实现前先 `ImmAssociateContext(hEdit, NULL)` 断开输入法，或改用 `SendInput` 发送硬件扫描码。

**第三级：剪贴板兜底**

把 `46 90 136` 放进剪贴板，面板上提示"已复制，请粘贴"。功能降级但不失败。

**可选动作**：配置项控制是否自动点 `COLOR_ADD` 和 `IDOK`。默认只填值不点按钮（避免误操作），提供"填值并确认"快捷方式用于连续改色。

### 3.5 面板窗口与焦点策略

这一节是整个设计里最容易翻车的地方，必须写清楚。

**表面需求**：面板置顶显示，但不该抢走颜色对话框的焦点——否则用户点一下面板，对话框就失焦，选完色还得点回来。

**解决办法**：给面板窗口加 `WS_EX_NOACTIVATE` 扩展样式。加了之后，点击面板不会激活它，颜色对话框保持前台。

```python
hwnd = panel.winfo_id()
ex = ctypes.windll.user32.GetWindowLongW(hwnd, GWL_EXSTYLE)
ctypes.windll.user32.SetWindowLongW(hwnd, GWL_EXSTYLE, ex | WS_EX_NOACTIVATE)
```

注意 tkinter 的 `winfo_id()` 在 Windows 上返回的是 Tk 内部窗口句柄，必要时用 `GetAncestor(hwnd, GA_ROOT)` 取顶层句柄再设置。

**但这带来一个新问题**：`WS_EX_NOACTIVATE` 的窗口无法获得键盘焦点，面板上那个 hex 输入框就打不了字。

**折中方案**（本设计采用）：

- 面板默认处于 `NOACTIVATE` 状态，可以点击色块、拖动色轮、点色板，全部正常。
- 用户点击 hex 输入框时，临时去掉 `NOACTIVATE` 并 `SetFocus` 到输入框；输入完成（回车或失焦）后恢复 `NOACTIVATE`。
- 吸管模式不需要键盘，全程 `NOACTIVATE`。

这样既保证常态下不打断对话框，又保证需要打字时能打字。

**DPI 处理**：面板创建前声明 DPI 感知（`SetProcessDpiAwareness`），否则在高分屏上会出现尺寸与位置偏差，鼠标取色的坐标也会错。

## 五、吸管设计

### 5.1 屏幕取色

1. 点"吸管"后 `SetCapture` 捕获鼠标，光标切成十字。
2. 抓一次全屏位图（`BitBlt` 从桌面 DC 复制）。**不逐点调 `GetPixel`**，那样每移动一像素就要一次系统调用，会有明显延迟。
3. 在面板上以 8 倍最近邻放大显示鼠标周围 24×24 像素，方便对准。
4. 松开鼠标取该点。

### 5.2 图片取色

两个入口：读剪贴板里的 `CF_DIB`，或接收拖入面板的图片文件（PNG / JPEG / TIFF）。

图片显示为可缩放画布，滚轮缩放，拖拽平移，点击取色。

### 5.3 采样与误差控制

**不取单点像素。** 以光标为中心取 5×5 邻域，三个通道分别取中位数作为输出值，同时计算邻域内的最大色差。

- 最大色差小于阈值（每通道 ≤ 6）：判定为纯色区域，采样可信。
- 超过阈值：面板显示警告"该点位于边缘或渐变区，建议重新取样"。

这一步是必要的。已发表插图的色块带抗锯齿边缘和 JPEG 压缩噪声，单点取样很容易吸到过渡色，得到一个"看着差不多、实际不对"的值。这类偏差在投稿时会被认为是配色不一致。

### 5.4 必须在面板上写明的局限

1. 屏幕与图片取到的是 sRGB 编码值，取决于原图的色彩空间。若原文插图是 CMYK 导出且转换不当，吸出的值与它在 Prism 中的显示不会完全一致。
2. 吸色能保证"和图里一致"，不能保证"符合规范"。期刊对色盲友好性有要求时，应使用内置色板而非逐点吸色。

## 八、风险与应对

| 风险 | 概率 | 应对 |
|---|---|---|
| 对话框不是标准 `#32770` | **已排除** | Phase 0 实测确认是 `#32770` |
| 控件 ID 与 `dlgs.h` 不符 | **已排除** | 706/707/708/712/1 全部吻合 |
| `WM_SETTEXT` 后预览不刷新 | 中 | 降级键盘模拟；或补发 `EN_CHANGE` |
| 火绒拦截窗口钩子或模拟输入 | 中 | 加程序白名单；降级为轮询检测 + 剪贴板兜底 |
| 面板抢焦点打断操作 | 高（若不处理） | `WS_EX_NOACTIVATE` + 输入时临时切换 |
| 高分屏下坐标错位 | 中 | 进程声明 DPI 感知 |
| Prism 升级后结构变化 | 低 | 控件 ID 与标题候选全部外置到配置 |

**总回退路径**：即使所有自动化都失效，工具仍可作为"色值参考面板"使用——查色、转格式、给出规范色板，然后手工粘贴。功能降级，但不归零。

## 九、能力边界（必须提前说清）

1. **只对 Windows 有效。** Prism Mac 版用的是系统调色板，机制完全不同。
2. **只能改颜色，不能改别的属性。** 线宽、字体、标记形状不在此列。
3. **不能批量。** 一次改一个对象的颜色。若要批量，需要走项目文件改写那条路（已评估，暂不推进）。
4. **依赖对话框存在。** 如果 Prism 某个版本改成内嵌颜色选择器（不再弹系统对话框），工具立即失效。
5. **需要常驻。** 工具必须在后台运行才能捕获对话框出现。若不接受常驻，只能做成"用时手动启动"。
