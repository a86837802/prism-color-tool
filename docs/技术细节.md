# 技术细节

记录这个工具为什么要这样实现，以及开发过程中踩过的坑。

## 为什么不写 Prism 插件

GraphPad 官方文档明确：

> "Does Prism have an API that can be called from other programs? No."

Prism 的脚本功能只能开/关项目、导入数据、导出图表，无法控制绘图属性（颜色、线型、字体）。所以不存在插件或 API 这条路。

## 为什么改的是系统对话框

官方文档另一句：

> "This brings up the custom color dialog, which is part of Windows and was not created by GraphPad."

那个要求输入三个数字的对话框是 Windows 通用颜色对话框（`comdlg32.dll` 的 `ChooseColor`），窗口类名 `#32770`。它的控件 ID 定义在 Windows SDK 的 `dlgs.h`：

| 常量 | 值 | 用途 |
|---|---|---|
| `COLOR_RED` | 706 | 红通道输入框 |
| `COLOR_GREEN` | 707 | 绿通道输入框 |
| `COLOR_BLUE` | 708 | 蓝通道输入框 |
| `COLOR_ADD` | 712 | 添加到自定义颜色 |
| `IDOK` | 1 | 确定 |

工具做的事只有两件：给这三个输入框发 `WM_SETTEXT` 写值，再用 `WM_GETTEXT` 读回校验。不注入进程、不挂钩子、不改任何文件。

由于这些 ID 是 Windows 的固定常量，界面语言不影响识别——中文版标题是「选择颜色」，英文版是 `Choose Color`，但控件 ID 一致。这也解释了为什么发版到 Prism 7–11 都能用。

## 透明度为什么要走滑块

Prism 在标准对话框上追加了两个控件：

| 控件 ID | 类名 | 说明 |
|---|---|---|
| 1116 | `msctls_trackbar32` | 滑块，位置 0–100 |
| 1117 | `Edit` | 显示 `80%` |

实测发现：**只写 1117 文本框时，滑块位置不动**（仍是 80），说明 Prism 读的是滑块而非文本。正确写法是两条消息：

```
TBM_SETPOS(滑块, 1, 目标值)                          ← 设置位置
WM_HSCROLL(对话框, (SB_THUMBPOSITION<<16)|目标值, 滑块)   ← 通知对话框响应
```

只发第一条滑块会动但对话框不响应，只发第二条会被忽略。

## 吸管的两处坑

### 抓屏缓冲区的行序

`win32ui.GetBitmapBits()` 返回的像素数据是**自上而下**排列，与 Windows DIB 的通用惯例（自下而上）相反。按惯例写 `index = ((height-1-y) * width + x) * 4` 会导致取色点上下镜像。

校准方法：用 `GetPixel` 逐点读取屏幕真实颜色，与缓冲区读取结果对照，选取屏幕上下差异明显的采样点（选中心附近的点会因为对称而测不出来）。

### Tk 的事件坐标

Tk 8.6 在 DPI 感知进程里，事件回调的 `x_root` 可能仍返回逻辑坐标（例如 1536×864），而抓屏缓冲区是物理像素（1920×1080）。两者混用会让取色点系统性偏移，越往右下偏得越多。

改用 `win32api.GetCursorPos()` 取坐标，与抓屏同一套物理坐标。

## 跨进程读写控件的注意事项

**读文本必须用 `WM_GETTEXT`**。`GetWindowText` 对别的进程的控件只返回缓存标题，对 Edit 控件直接返回空，会造成"写入失败"的误判。

**缓冲区单位**：`PyMakeBuffer` 的单位是字节，而 `WM_GETTEXT` 的长度参数单位是字符，UTF-16 下要乘 2，否则只能读到第一个字符。

## 打包

```bash
pyinstaller --onefile --windowed --name PrismColorTool \
  --distpath release --workpath .build --specpath .build \
  --paths src src/prism_color_tool_v1.py
```

**使用 conda 环境时务必先隔离 PATH**：

```bash
PATH="/path/to/env:/path/to/env/Library/bin:/c/Windows/System32:/c/Windows" \
  pyinstaller ...
```

否则 PyInstaller 会沿 PATH 抓到其他 conda 环境的 Tcl/Tk 运行时。典型症状是 exe 启动时报：

```
version conflict for package "Tcl": have 8.6.14, need exactly 8.6.13
```

原因是运行时 DLL 来自 base 环境（8.6.14），而数据目录取自当前环境（8.6.13）。隔离 PATH 后两者一致，问题消失。

## 单实例保护

用命名互斥量。关键点：**返回的句柄必须存进全局变量**，否则会被垃圾回收释放，互斥量消失，第二个实例就检测不到了。这个坑很隐蔽——程序看起来"正常工作"，只是保护失效。

```python
_MUTEX_HANDLE = win32event.CreateMutex(None, False, MUTEX_NAME)
if win32api.GetLastError() == winerror.ERROR_ALREADY_EXISTS:
    # 已有实例，提示后退出
```

## 托盘菜单的坑

`TrackPopupMenu` 默认**不返回**用户选了哪一项，只返回 0，选择结果通过 `WM_COMMAND` 异步发出。必须加 `TPM_RETURNCMD` 标志才能拿到选中项 ID：

```python
command = win32gui.TrackPopupMenu(
    menu, TPM_LEFTALIGN | TPM_RIGHTBUTTON | TPM_RETURNCMD,
    x, y, 0, hwnd, None)
```

没加这个标志时，菜单能弹、能点、点完就关，就是不执行任何操作。

## 排查

工具没反应时，先跑 `tools/dialog_probe_v1.py`，它会把当前所有 `#32770` 窗口的控件树打印出来，据此判断控件 ID 是否与预期一致。

## 已知限制

1. 仅支持 Windows。macOS 版 Prism 使用系统调色板，机制完全不同。
2. 只能改颜色与透明度。线宽、字体、标记形状不在范围内。
3. 不解析 Prism 项目文件。工具操作的是对话框，不是数据。
4. 单实例运行。
5. 若 GraphPad 未来改为自绘颜色选择器，本工具将失效。
